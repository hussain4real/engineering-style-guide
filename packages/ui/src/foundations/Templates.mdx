# Engineering Templates

MILAHA engineering delivery documents should use these templates as the required baseline. The Markdown files are the source of truth so teams can copy them into project repositories, review them in pull requests, and keep changes versioned with the work.

## Shared Rules

Every template must keep these fields:

- `title`
- `owner`
- `status`
- `reviewers`
- `last_updated`
- `related_links`
- `source_materials_reviewed`

Use the `source_materials_reviewed` section to show which inputs were checked before writing the document. A template is not ready for review if this section is empty.

## Phased Implementation Statuses

Use only these statuses in phased implementation plans:

- `Not started`
- `In progress`
- `Blocked`
- `Ready for review`
- `Complete`

## Review Expectations

- The owner is accountable for keeping the document current.
- Reviewers should be named before the document enters review.
- Business and technical decisions should link to their source material.
- Open risks and dependencies should be visible before implementation starts.
- Approved documents should be updated when scope, architecture, or release plans materially change.
